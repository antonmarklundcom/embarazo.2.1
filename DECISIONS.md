# DECISIONS.md — Nido v2.1

Every non-obvious assumption made while building the investor MVP. Append-only.

## Stack & scaffolding
- **Next.js 15 (App Router) + React 19 + TypeScript strict.** Hand-written scaffold (no `create-next-app`) so configs match the spec exactly and nothing is re-scaffolded later.
- **Tailwind 3.4** (not v4) for stability with the current Next preset. Palette and radii from §3 are encoded as theme tokens (`cream`, `petrol`, `terracotta`, `rose`, `sage`, `ink`, `muted`, `whatsapp`, `sand`).
- **Nunito Sans via `next/font`** (weights 400/500), the spec's first font choice.
- **No `output: 'export'`** — standard SSR build/start for Hostinger.

## PWA
- **Serwist (`@serwist/next` v9)**, SW source at `app/sw.ts` → `public/sw.js`, disabled in dev (§9).
- Precache = app shell + all 42 `/semana/[n]` + all 8 `/guias/[slug]`. These are statically generated (`generateStaticParams`), so they enter `__SW_MANIFEST` automatically.
- Network-first with cache fallback for `/api/v1/placements` and `/api/v1/directory`.
- `public/sw.js` is **git-ignored** (build artifact). Regenerated by `npm run build`.

## Data layer
- **Dexie/IndexedDB** for all on-device health data. `lib/db.ts` lazily instantiates so the module is import-safe in server components.
- `db()` throws if called server-side, guarding the privacy boundary by construction.
- **`wipeAllData()`** deletes the entire IndexedDB database (not just rows) and is paired with `clearPin()` in Ajustes.

## Privacy / crypto
- Optional PIN derives an AES-GCM key via **PBKDF2 (150k iterations, SHA-256)** in WebCrypto. We persist only a random salt + an encrypted verifier token in `localStorage`; never the PIN.
- **Honest copy** (§5): the privacy text says this relies on per-origin isolation + device encryption and is *not* bank-grade. No SQLCipher/hardware-keystore claims.
- **Assumption:** disabling a PIN does not retroactively decrypt already-encrypted notes; they remain encrypted until re-saved. Documented as acceptable for the MVP.
- WebCrypto byte buffers are allocated as `Uint8Array<ArrayBuffer>` (helpers in `lib/crypto.ts`) to satisfy the stricter `BufferSource` typing in TS 5.7 + current lib.dom without `any`.

## API routes (thin, seed-backed)
- All inputs **zod-validated with `.strict()`** plus an explicit allowed-key check, so any param outside the whitelist returns **400** — enforcing the privacy contract at the boundary (§7). Covered by tests.
- `placements` whitelist: `trimester`, `department`. `directory` whitelist: `department`, `category`, `q`.
- **`trimester: 0`** on a placement means "all trimesters" and always passes the trimester filter.
- `Cache-Control: public, max-age=3600`, **no Set-Cookie** anywhere.
- `/api/v1/go/[id]` looks up a placement *or* a directory listing by id and 302s to the `wa.me` URL. Attribution is fire-and-forget to `SHEETS_WEBHOOK_URL` if set, never awaited, never blocking, logs nothing identifying.
- **No `/api/v1/lead`, no fan-out orchestrator** — intentionally deferred (§7). Conversion at v1 is the WhatsApp redirect only.

## Content
- **All 42 weeks** authored with non-placeholder es-PY voseo content and a realistic Paraguayan size-comparison progression (semilla de chía → mamón → palta → choclo → coco → sandía).
- Weeks 1–2 honestly state there is no embryo yet (weeks counted from LMP). Measurements appear only once the embryo/fetus is measurable; crown-rump up to ~week 20, then crown-heel.
- `WeekInfo.trimester` is **derived** from the week via `getTrimester`, so it can't drift out of sync with the content.
- **8 guías** authored as in-repo HTML in `lib/seed/articles.ts` (chose typed TS over MDX to avoid an extra loader for the MVP). Each carries `reviewedBy`; the visible byline uses `NEXT_PUBLIC_MEDICAL_REVIEWER`.

## Seed / directory / placements
- Directory + placements are clearly-commented **placeholders** with invented names and non-working `+595981000xxx` numbers, spread across Capital, Central, Alto Paraná and Itapúa.
- `lib/wordpress.ts` is the documented optional hook: returns seed unless `WP_API_URL` is set; the WP integration is **not built** (TODO-marked field mapping only).

## Icons
- PWA icons (192, 512, maskable-512) are generated with a dependency-free Node script (`scripts/gen-icons.mjs`, zlib + manual PNG) in palette colors. Re-runnable; output committed under `public/icons/`.

## Onboarding / routing
- First-run gate lives **in `app/(app)/page.tsx`** and renders `<Onboarding>` in place when no profile exists — no `(onboarding)` route group, no redirect (§4). Exactly one `page.tsx` resolves to `/`.

## Testing
- Vitest. Tests cover `lib/pregnancy.ts` math and the placements/directory param-whitelist rejection (§11).

## v5 — Derechos, Emergencia, Guaraní, Carné
- **"Tus derechos y beneficios" (`/derechos`)**: typed catalog in `lib/derechos.ts` keyed by work situation (IPS / sin IPS / no trabaja) and phase. Legal specifics verified against Ley 5508/2015 (18 semanas, extensión a 24, lactancia 90/60 min, paternidad 2 semanas, fuero hasta 1 año), Ley 7383/2024 (hasta 4 h pagas para controles prenatales), Ley 5099/2013 (gratuidad MSPBS), IPS (subsidio 100%, reposo desde semana 38, ≥4 meses de aporte) y CT arts. 261+ (bonificación familiar 5%). **Amounts/rules must be re-verified before launch and periodically**; the UI always shows the "no es asesoría legal" disclaimer. The user's work situation is component state only — never persisted, never transmitted.
- **Leave-date math** (`computeLeavePlan`): earliest start = FPP − 14 días; end = start + 126 días; IPS reposo emitible desde FPP − 21 días (semana 38). Unit-tested.
- **Emergencia (`/emergencia`)**: 141 (SEME) and 911 as `tel:` links — national short codes, safe to hardcode. Sanatorio + emergency contact are optional **non-indexed** Profile fields (no Dexie version bump needed). Alarm signs live in `lib/emergency.ts`, mirroring the guía.
- **Guaraní (jopara)**: alarm signs carry `textGu`, shown inline under the Spanish on `/emergencia` with `lang="gn"`. Register is deliberately simple jopara (Spanish clinical nouns kept), matching MSPBS material style. ⚠️ **Pending native-speaker review before public launch** — treat current strings as drafts.
- **Carné perinatal (`/herramientas/carne`)**: Dexie **v4** adds `carnePhotos` (page photos, downscaled ≤1280px via shared `lib/images.ts`) and `clinical` (single row: bloodType/allergies/notes). Blood type + allergies also surface on `/emergencia`. Copy explicitly says the photos do not replace the paper carné.
- **SOS pill** in the header links to `/emergencia` from every screen; deliberately not a bottom-nav tab to keep the 5-tab layout.

## Phase 0 hardening (July 2026)
Prompted by a full app review (see `docs/REVIEW-AND-LAUNCH-PLAN.md`). Code-only fixes with no external data dependency.
- **Backup/restore** (`lib/backup.ts`, Ajustes "Copia de seguridad"): exports every Dexie table as one JSON file, converting `Blob` fields (belly photos, carné photos) to data URLs. Restore is a full replace (transaction: clear then bulkAdd) — merge semantics were judged unnecessary complexity for a device-local single-user app. This is the top fix from the review: previously any lost/reset device meant total data loss with zero recovery path.
- **`navigator.storage.persist()`** requested on Ajustes mount; status surfaced to the user (browsers may otherwise silently evict IndexedDB under storage pressure).
- **`/privacidad` and `/terminos`**: DRAFT text describing the app's actual current behavior honestly. Explicitly marked as needing founder/legal review before launch (§4.6 of the review doc) — do not treat as final legal copy.
- **Error/404/offline pages**: `app/(app)/error.tsx` + `app/(app)/not-found.tsx` keep the app shell (header/nav) visible; `app/global-error.tsx` is the last-resort root-layout boundary (must self-provide `<html>/<body>` per Next.js convention, deliberately has zero Tailwind dependency); `app/offline/page.tsx` is wired into `app/sw.ts` via Serwist's `fallbacks` option for any non-precached navigation request made offline.
- **Video gallery gated**: every seed video in `lib/seed/videos.ts` used the same placeholder YouTube ID (`dQw4w9WgXcQ`) — shipping it would show a rickroll to a pregnant user. `PUBLISHED_VIDEOS` filters placeholders out; `/guias/videos` and its two nav entry points hide themselves automatically until `lib/seed/videos.ts` gets real IDs, with no other code change needed.
- **Onboarding due-date entry**: `components/Onboarding.tsx` previously only accepted LMP, forcing users who only know their ecografía-derived due date to guess. Added the same FPP toggle Ajustes already had, reusing `lmpFromDueDate`. Also wrapped `save()` in try/catch — it previously failed silently (e.g. under private-browsing storage restrictions) with no user feedback on the very first interaction.
- **Removed `maximumScale: 1`** from the viewport export (`app/layout.tsx`) — it disabled pinch-zoom app-wide, a WCAG 1.4.4 violation for a health app.
- **`app/sitemap.ts` / `app/robots.ts`**: exposes the 42 week pages + 8 guías for indexing; personal tool pages (`/herramientas/*`, `/ajustes`) stay disallowed since they carry no public content.
- **Rate limiting** (`lib/rateLimit.ts`): simple in-memory sliding window (30 req/min/IP) on `/api/v1/go/[id]` to blunt casual spam of the fire-and-forget attribution webhook. Explicitly not built to survive a distributed attack — acceptable for this route's stakes; state resets on cold start.

## Phase 1 — pre-launch code (executing Fable 5 build plan, July 2026)
See `docs/BUILD-PLAN.md`. Name stays TBD, so nothing here introduces a product name; the old name survives only as internal identifiers until R1.
- **Install UX (P1.1)**: `lib/useInstallPrompt.ts` returns a discriminated state — `prompt` (Chromium `beforeinstallprompt`, deferred + replayed on tap), `ios` (iOS Safari, which has no such event → manual "Agregar a inicio" instructions), or `unavailable` (already standalone via `display-mode`/`navigator.standalone`, or no signal). `<InstallCard>` self-hides on `unavailable`, so it's safe to mount on Home + Ajustes.
- **Update toast (P1.2)**: `<UpdateToast>` in Providers listens for SW `controllerchange`, but only after an initial controller existed — avoids a false "nueva versión" on the very first SW claim. skipWaiting means the new worker is already active, so the only action offered is reload.
- **Privacy-safe analytics (P1.3)**: `POST /api/v1/ping` mirrors the read-API privacy boundary — zod `.strict()`, only `{event, mode, trimester?, department?}`, 204, no Set-Cookie, forwarded fire-and-forget to `ANALYTICS_WEBHOOK_URL` (no-op 204 when unset). `<AnalyticsPing>` sends one "open" per day keyed on a stored **date string**, never a generated id — so no device is followable across days. Writes the date before sending to prevent double-fire. Disclosed in `/privacidad`. Tested (whitelist rejection, bad JSON, rate limit).
- **Metadata (P1.4)**: manifest `shortcuts` (Emergencia, Herramientas); per-`/semana/[n]` description already existed. OG **image** deliberately deferred to branding/R1 — any OG image carries the product name/logo, which is TBD.
- **ESLint (P1.5)**: added `eslint` 9 + `eslint-config-next` + `@eslint/eslintrc` FlatCompat (`eslint.config.mjs`, `next/core-web-vitals` + `next/typescript`); `npm run lint` added to CI. Fixed two pre-existing mis-placed `no-img-element` disable directives (the `<img>` renders a `blob:` URL, which `next/image` can't optimize — the disable is correct, it was just on the wrong line). Remaining findings are non-blocking warnings.
- **Landing page (P1.6)**: `/conoce`, static, outside the `(app)` group so it renders without the app shell — a front door for non-users with feature summary, privacy pillar, and SEO links to every guía. Name-free (TBD). Added to sitemap + linked from 404.
- **E2E (P1.7)**: Playwright (`e2e/*.spec.ts`, `test:e2e`, separate CI job) against `next start`. Uses the pre-installed Chromium if present, else Playwright's bundled browser. Covers onboarding (LMP, due-date, planeando), symptom save, backup download, and offline serving.
- **⚠️ Offline was actually broken — fixed via P1.7.** The e2e offline test revealed that the earlier DECISIONS claim ("all 42 `/semana/[n]` + guías precache automatically") was **false**: `@serwist/next`'s manifest precaches build assets (JS/CSS/fonts/icons, 66 entries) but **not the SSG HTML documents**, and `/offline` wasn't precached either — so offline navigation to content pages failed with `ERR_FAILED`. Fix in `app/sw.ts`: (1) a runtime `NetworkFirst` route matched on `request.destination === "document"` (cache `nido-pages`) placed **before** `defaultCache`, so each visited page opens offline; (2) `/offline` added explicitly to `precacheEntries`; (3) `navigationPreload` turned **off** — with it on, an offline navigation waited on the failing preload instead of falling back to cache. Verified: a visited week page now renders with the network off; unvisited pages hit the `/offline` fallback.
