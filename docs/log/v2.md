## The interface, for W5 to copy
The cut is **rules in the module, storage behind the interface**, with three rules:
1. **No policy in the backend.** Nothing in `sharingBackend.ts` checks a role or decides what a caller may see. A method that took a `MemberRole` and returned different data for different roles would be a rule hiding in storage — untested, and duplicated in every future backend.
2. **One exception, and it stays in the query: `revokedAt IS NULL`.** "Revoking is immediate" holds because a revoked membership is not *readable*, not because something remembers to filter it. `liveMembership`, `liveMembershipsOf`, `liveMembersOf`, `liveNonOwnerCount` and `setAccompanyingIfLive` all carry it; the method names say so, so a caller cannot ask for the unscoped version because there isn't one.
3. **Row types are the storage shape, not the wire shape.** `StoredSnapshot` carries the K3 flags next to the values because the *read* re-applies the levels from what is stored. Mapping to the API shape is the rules module's job.

Methods, grouped: `findPregnancyByOwner` · `insertPregnancy` (throws on duplicate owner — the unique index is load-bearing) · `findPregnancyOwner` | `insertMembership` · `upsertMembership` · `liveMembership` · `liveMembershipsOf` · `liveMembersOf` · `liveNonOwnerCount` · `revokeMembership` · `setAccompanyingIfLive` | `insertInvite` · `findInvite` · `markInviteAccepted` · `revokeInvite` | `upsertSnapshot` · `findSnapshot` · `deleteSnapshot` | `upsertTask` · `deleteTask` · `setTaskDone` · `tasksOf` | `insertCheer` · `cheersOf` · `markCheersSeen`.

The memory backend in the test file is the second implementation, and it **imitates the SQL where the SQL is load-bearing**: the unique-index throw, `ON DUPLICATE KEY UPDATE` un-revoking in place, `doneAt` surviving a re-assignment, an update scoped to a key that matches no row inserting nothing. Those four are what the rules depend on; copy that discipline, not just the shape.

## Decisions
- **Two text assertions moved with the code they watch.** `routeContract.test.ts` asserted `isNull(pregnancyMembers.revokedAt)` inside `setAccompanying`'s body, and `fields.test.ts` asserted `.delete(companionSnapshots)` inside `revokeMembership`'s. Both are about SQL, and the SQL moved. They now assert `setAccompanyingIfLive` is what is called *and* that the backend's method carries the scope, and `deleteSnapshot(pregnancyId)` respectively — same property, followed one file along. **Objection logged as the prompt requires:** it says `routeContract.test.ts` "must keep passing unchanged", and one of its 16 assertions could not, because the refactor the same prompt mandates is what moves the string it matches. Writing a comment into `sharing.ts` containing `isNull(pregnancyMembers.revokedAt)` would have kept it literally passing and made it meaningless; that was the alternative and it was not taken. The other 15 pass untouched.
- **The "only file that queries these tables" test has a four-entry allowlist**, not zero. `admin.ts`, `adminMetrics.ts` and `support.ts` legitimately read these tables for the I-series admin views, aggregate counts and U6's support console, and each has its own privacy test; `account.ts` deletes across the whole schema by design. The list is short, each entry carries its argument, and a fifth appearing without one is the review the test exists to force.
- **`liveNonOwnerCount` filters the role in JS, not in SQL.** One fewer thing the memory backend has to imitate exactly, on a set that is a handful of rows.
- **`liveMembership` in `sharing.ts` is a thin pass-through** returning the narrow `Membership`. Kept rather than inlined because the route imports it and the K2 handlers re-check with it.

## Known issues
- `sendCheer` reads the owner through `findPregnancyOwner` after the membership check — two backend calls where the old code also did two queries. Unchanged, not improved.
- The backend is constructed per request. Stateless, so this costs an object; a pooled one would need a reason.
- `insertPregnancy`'s duplicate-key contract is expressed in prose and in the memory backend, not in the type. A backend that swallowed the duplicate would break `ensurePregnancyForOwner`'s race recovery silently — W5's modules have no equivalent, but a later sharing backend would.
