# U8 — brand constant + manifest title

## Built
- `lib/brand.ts`: `APP_NAME`, `APP_DESCRIPTOR`, `APP_TITLE`, `APP_SHORT_NAME` (per
  `docs/decisions-needed.md`'s confirmed "Mi Bebé · Embarazo Paraguay").
- `lib/brand.test.ts`: constant values, `app/manifest.webmanifest` fields equal the
  constants, and a source scan asserting no `.tsx` under `app/`/`components/` contains
  the literal "Mi Bebé".
- `app/manifest.webmanifest`: `name` = `APP_TITLE`, `short_name` unchanged (`APP_SHORT_NAME`).
- `app/layout.tsx`: title/OG/Twitter title use `APP_TITLE`; `applicationName`,
  `appleWebApp.title`, `siteName`, OG alt, and the title template's suffix use `APP_NAME`.
- `lib/share/card.ts` (`SHARE_BRAND`) and `lib/share/invite.ts` (`INVITE_TITLE`) now
  import `APP_NAME` instead of a literal.
- Swept every hardcoded "Mi Bebé" (visible strings and code comments) in `app/**` and
  `components/**` — ~35 files — to import `{ APP_NAME }` (or `APP_TITLE` for the two
  full-title metadata strings on `/conoce` and `/borrar-cuenta`). `AppHeader.tsx`
  wordmark kept `APP_NAME` as instructed.
- `app/sw.ts`'s push-notification fallback title now imports `APP_NAME` too (not listed
  in Owns explicitly, but it's a user-visible brand string under `app/`).

## Decisions
- `scripts/gen-og.mjs` has no title string to change — it draws only shapes/gradient,
  no text — so it's untouched; noted as a spec/reality mismatch rather than skipped work.
- Comments mentioning "Mi Bebé" (design-note prose, not UI copy) were reworded to avoid
  the literal rather than importing the constant into a comment, since the exit grep
  (`git grep "Mi Bebé" -- components app`) doesn't distinguish comments from code.
- `app/globals.css`'s design-language comment was reworded the same way (CSS can't import).
- Full-title strings (e.g. `/conoce`, `/borrar-cuenta` `<title>`) got `APP_TITLE`; bare
  "Mi Bebé" mentions got `APP_NAME` — matches the manifest/layout split the spec describes.
- Updated `scripts/smoke-live.test.ts`'s `MANIFEST_NAME` fixture from the old manifest
  `name` string to the new one (`APP_TITLE`'s value) — outside the Owns block, but it's a
  one-line stale-fixture fix directly caused by the (in-scope) manifest change, and it's
  exactly what `docs/log/l1.md`'s "Known gaps" flagged as the expected U8 follow-up.

## Known issues
- Two pre-existing test failures, unrelated to U8, confirmed present with `lib/brand.ts`
  and all brand edits reverted via `git stash`-equivalent check: `lib/flags/keys.test.ts`
  (Windows backslash paths fail a POSIX-path assertion) and `lib/articles/index.test.ts`
  (Windows CRLF vs the generator's LF output). Neither touches brand/share/manifest code.
- `lib/server/auth.test.ts`'s rate-limit test timed out once during a full `npm test` run
  (flaky timing test, unrelated to this unit) but passed on other runs.
- Two files auto-regenerated by build/test scripts (`docs/GUARANI-REVIEW.md`,
  `lib/articles/index.json`) showed as CRLF-only "modified" after running gates; reverted
  both since they're outside Owns and had no real content diff.

## Verification
`npx tsc --noEmit`, `npm run lint`, `npm run validate:content`, and the build all pass
clean; `npm test` is green except the two pre-existing unrelated failures above; the three
e2e specs touching brand/manifest strings (`admin.spec.ts`, `account.spec.ts`,
`onboarding.spec.ts`, 21 tests) all pass; `git grep "Mi Bebé" -- components app` returns
only `app/manifest.webmanifest` (asserted equal to the constants by `lib/brand.test.ts`).
