# U2 — I4 AI usage & spend panel

## Built
- `lib/server/aiBaby.ts`: `generateBabyImage` gains an `isPaused` parameter
  (default: real `getFlag("ai_baby_paused")`), checked strictly *after*
  `isConfigured()` — the flag can only add a stop on top of
  `AI_BABY_ENABLED`, never substitute for it. A paused request returns the
  same `{ ok: false, failure: "disabled" }` shape the kill switch already
  produces, so the client needs no new case.
- `lib/server/aiSpend.ts`: `summariseMonth` (pure) + `aiSpendReport` (current
  UTC month, then the previous one) — generations by status, spend in USD,
  distinct users, users at/over quota, the configured quota. Reads only
  `userId`/`status`/`costUsdMicros` from `aiGenerations`, which has no
  prompt/photo column to begin with.
- `AI_BABY_ALERT_SHARE` (`.env.example`, default 0.8): `aiBabyAlertShare()`,
  same fail-closed shape as the rest of `lib/ai/quota.ts`.
- `/admin/ia`: this + previous month's spend vs the ceiling (with the ₲
  approximation), generated/failed/pending counts, distinct users and users
  at quota, an alert banner past the configured share, and a Pausar/Reanudar
  control.
- `components/admin/AiSpendControls.tsx`: calls the **existing** `toggleFlag`
  server action from `/admin/flags` — no second write path, no second audit
  path, only the labels are specific to this screen.
- `app/admin/layout.tsx`: one nav link ("IA").

## Decisions
- **`app/admin/page.tsx` has no slot for a spend-alert banner** — adding one
  would mean editing a file outside this unit's Owns block. Left to U11 per
  the prompt's own instruction; noted here so it isn't lost.
- **`e2e/admin.spec.ts` (not in this unit's Owns block) got one line**:
  `/admin/ia` appended to its shared `ADMIN_URLS` pinned list. That file is
  the single existing mechanism for "every /admin URL 404s for a
  non-admin", which the prompt's own exit criteria require covering for this
  route — same append-only spirit as `ADMIN_ACTIONS` growing in U1, just not
  named in this prompt's Owns line.
- `isConfigured()` itself stays synchronous and env-only (unchanged, still
  used by `app/api/v1/ai/baby/route.ts`'s early 404); the async pause check
  lives inside `generateBabyImage` instead, via dependency injection (same
  pattern as `callModel`), so the paused branch is provable in CI with no
  MySQL rather than requiring `isConfigured` to become async everywhere it
  is called (which would have meant editing that route file, also outside
  Owns).
- "Users at quota" counts `used >= quota` (reached), a display stat — the
  enforcement rule in `quotaVerdict` is `used > quota` (exceeded) and is
  unchanged.

## Known issues
- The alert banner is US-month-scoped to the current month only; the
  previous month's card never alerts (it is already closed).
- No live e2e coverage of the Pausar button's actual effect (CI has no
  database/OAuth); covered by unit tests over `generateBabyImage`'s new
  parameter and by the existing `setFlag`/`toggleFlag` tests.
