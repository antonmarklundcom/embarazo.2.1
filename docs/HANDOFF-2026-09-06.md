## 2. Founder decisions made this session

**Image style (week-by-week hero art).** Landed on a semi-realistic,
softly-lit 3D render style — anatomically recognisable but idealised, warm
golden lighting, a soft luminous glow baked into the edges of the subject.
No genitalia shown (side-curled pose, legs drawn up, at every week). The
39/42 week renders and the fruit/vegetable size-comparison objects
(`lib/weeks.ts`'s `sizeComparison`, already Paraguayan produce — mamón,
mandioca, ananá, zapallo, etc.) should be generated in this same lighting
vocabulary so they read as one family, on **flat solid backgrounds** (not
gradients) so `rembg` can cut them out cleanly. The founder is running
generation + background removal locally; images land in the repo once
approved.

**Planned UI on top of those images**, once the assets exist:
- A **background-theme selector** (the joyful Paraguayan-motif ideas from
  this session's chat — soft golden halo, ñandutí lace medallion, sun/moon,
  stevia-leaf wreath, guardian-angel wings, starry sky — kept symbolic/
  abstract rather than depicting a specific religious figure, so they read
  as universal blessing/warmth to any user regardless of belief). Backed by
  transparent-background renders composited via CSS, so themes are ~6
  reusable assets, not 6× the week-image count.
- A **show/hide toggle for the fruit comparison**, stored as a local
  preference the same way other settings are.
- **Accurate relative sizing**: `lib/weeks.ts.lengthCm` already exists per
  week; add a matching real-world size (cm) per fruit/vegetable so the baby
  and the fruit render at proportionally correct relative scale on screen,
  not just as two same-sized icons side by side.
- **One baby art style only** — explicitly rejected offering multiple
  swappable baby styles (3–10 styles × 42 weeks was judged not worth the
  asset/precache-size cost for a one-time-per-user decision). The
  background theme is where the personalisation value actually is.

**Monetisation.** No in-app payment or subscription path that sits
alongside or routes around Google Play Billing — ruled out explicitly,
including for any future Play Store listing (Play's policy already
forbids an alternate billing path for digital goods on Play; this decision
just makes that the plan rather than something to work around). Near-term
revenue is:
1. **Sponsorships/partnerships** — B2B, invoiced outside the app. I2's
   dashboard (WhatsApp clicks, click-through by department/category) is
   exactly the number a sponsor deck needs, and already ships.
2. **The founder's own physical products in Paraguay, later.** Exempt from
   Play Billing (same principle as any goods-shipping app — Play Billing
   only governs digital goods/subscriptions sold through the app).

A **digital, Play-billed paid tier stays possible later** (e.g. an "Ask
Flo" AI assistant behind a subscription, per the old MVP-AND-MONETISATION
plan) but is explicitly deferred — no ledger/screens work now. See I3's
note in `BUILD-PLAN.md`.

**E4 "Beneficios" tab → replaced with a "Recomendados" rail.** No sponsors
are signed yet, so building a sponsor-deals browsing surface has nothing
real to show. Reuses the identical card + WhatsApp-order UI and the same
empty-until-real-data gate as the directory, but seeded with the founder's
own future products / curated free resources instead. Same shipped
infrastructure serves sponsor deals later without rework. See `BUILD-PLAN.md`
E4.

**D6 training/exercise classes → rescoped, unblocked.** Images + text only,
no video (multiple step images allowed per exercise). Removes the
video-asset blocker that had this at lowest priority.

**Go ahead on:** I1 (admin support console gaps — force a resync, revoke a
device/family member, restore a soft-deleted record), D7 (tool polish —
contractions 5-1-1 hint, kicks-history nudge), I4 (AI usage/spend panel),
I5 (feature-flag panel, minus the broadcast-messaging half — not asked
for this session, only the flag-toggle half).

## 3. AI feature inventory (founder asked "what do we use AI for" — answer for reference)

1. **AI Baby Image — BUILT.** `/herramientas/bebe-ia` → `POST /api/v1/ai/baby`.
   Blends 1–2 uploaded parent photos into a generated newborn portrait via
   Gemini (`gemini-2.5-flash-image`), for entertainment only ("no es una
   predicción"). Opt-in with explicit consent; photos discarded after the
   request, nothing stored server-side. Gated by `AI_BABY_ENABLED` +
   `GEMINI_API_KEY` (404s entirely without both), a per-user monthly quota
   (`AI_BABY_MONTHLY_QUOTA`), a global monthly spend ceiling
   (`AI_BABY_MONTHLY_SPEND_CEILING_USD`), and per-call cost tracking
   (`AI_BABY_COST_MICROS`) in the `aiGenerations` table. This is exactly
   what I4 (AI usage/spend panel) puts a UI in front of.
2. **Symptom Insight — NOT AI.** `components/SymptomInsight.tsx` is
   rule-based pattern matching over the user's own on-device data against
   static text templates. No model call, nothing sent anywhere. Gated on a
   configured medical reviewer for editorial reasons, not a kill switch.
3. **"Ask Flo" AI health assistant — PLANNED ONLY, no code.**
   `docs/FEATURE-MAP.md` F2 / `docs/MVP-AND-MONETISATION.md`: a
   conversational Q&A assistant, explicitly flagged as the highest-risk
   feature in those docs and previously framed as the paid-tier anchor. Per
   §2 above, if/when this gets built it should ship free with the same
   quota/cost-ceiling pattern as the AI baby image — not paywalled — since
   subscriptions are off the table for now. Needs a mandatory
   escalation-to-real-care path per the existing docs regardless of
   monetisation.

## 4. What I4/I5 actually are, in plain terms

- **I4 AI usage/spend panel.** Right now, seeing how much the AI Baby
  feature generated/cost this month, or pausing it, means reading database
  rows directly or changing an env var and redeploying. This adds an admin
  screen showing usage against quota and spend against the ceiling, with an
  on/off toggle — same information, a click instead of a deploy.
- **I5 feature-flag panel** (flag-toggle half only, per §2). Several
  features (video gallery, the new Recomendados rail, AI baby) are gated by
  flags that currently only flip by redeploying. This adds a panel to flip
  them from the app itself. The broadcast-push half of I5 is untouched —
  not asked for this session.
