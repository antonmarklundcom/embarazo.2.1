# L1 — live smoke script

**What it checks** — `scripts/smoke-live.mjs` hits a deployed instance and prints one
PASS/FAIL row per check, exiting non-zero on any failure:

- `GET 200` on `/`, `/semana/20`, `/herramientas`, `/conoce`, `/borrar-cuenta`, `/privacidad`.
- The enforced `Content-Security-Policy` header on `/`, and no `Content-Security-Policy-Report-Only`
  header left behind.
- `/borrar-cuenta`'s HTML actually offers a way to reach a human (a `mailto:` or `wa.me/` link, and
  not the "Falta configurar" placeholder) — a live proxy for whichever of `NEXT_PUBLIC_SUPPORT_EMAIL`
  / `NEXT_PUBLIC_BUSINESS_WHATSAPP` the deployment has set, since the script itself has no way to know
  the server's env at request time.
- `/manifest.webmanifest` parses and its `name` matches `lib/brand.ts` if that file exists yet (it
  does not, pre-U8), otherwise the `name` baked into this checkout's `app/manifest.webmanifest`.
- `/sw.js` is served with a JavaScript content type.
- `GET /api/v1/directory` (no query) returns 200 JSON; `GET /api/v1/directory?foo=1` returns 400.
  `app/api/v1/directory/route.ts` (J3) now rejects *any* query parameter — it dropped the old
  `department`/`category`/`q` whitelist entirely — so the "good" request here is a bare path and any
  parameter at all is the "bad" one. The plan doc's `?department=central&trimester=2` example predates
  that change; the check matches the route as it exists today, per the dispatch's instruction to read
  the route for the whitelist rule.
- `/api/auth/providers`: 200 (accounts on) or 404 (local-only) both pass — the row exists to report
  which mode is live, not to gate it.

Every request uses global `fetch` with its own 15s timeout via `AbortController`, so one hung request
fails only its own row.

**How to run** — `npm run smoke:live -- https://<host>`, or directly:
`node scripts/smoke-live.mjs https://<host>`. With no argument it prints usage and exits 2.

**Tests** — `scripts/smoke-live.test.ts` stubs `globalThis.fetch` and drives `main()` directly (it
returns an exit code rather than calling `process.exit` itself, so tests can assert on it without
killing the test process). It lives under `scripts/`, not `lib/`, since it is testing a script rather
than an importable library module; `vitest.config.mts`'s `include: ["**/*.test.ts"]` picks it up with
no config change — confirmed by `npm test` running it.

**Known gaps**
- The manifest-name check reads `lib/brand.ts` from disk with a regex (`name\s*[:=]\s*["'\`]...`)
  rather than executing it, to stay dependency-free; once U8 lands, if its export shape is not a
  simple `name: "..."` string, the regex needs a look.
- The support-channel check is a proxy (looks for a live `mailto:`/`wa.me` link and the absence of
  the "no channel configured" placeholder) rather than comparing the exact configured value, since the
  script cannot read the deployed server's environment from the client side.
- No check exercises accounts-on `/api/auth/providers` (200) against a live OAuth deployment; the test
  suite only covers the 404 (local-only) path per the dispatch's required coverage.
