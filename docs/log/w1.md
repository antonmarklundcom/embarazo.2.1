# W1 — always-on CI fast lane

## Built
- `.github/workflows/ci.yml`: new `fast` job — `checkout`, `setup-node` 22
  (npm cache), `npm ci`, `npx tsc --noEmit`, `npm run lint`, `npm test`,
  `npm run test:db`. No build, no browser, no `validate:content`.
  `timeout-minutes: 10`.
- Top-level `pull_request.types` widened from `[labeled]` to
  `[opened, synchronize, reopened, labeled]` so `fast` sees every PR push;
  `build` keeps its own `if` gate (push to `main`, or the `run-ci` label) so
  it is unaffected by the wider trigger set.
- `fast`'s own `if` restricts it to the `opened`/`synchronize`/`reopened`
  actions, so a `labeled` event (e.g. relabelling) does not also re-run it.
- `build` unchanged except `actions/checkout@v4` → `v7` and
  `actions/setup-node@v4` → `v7` (both occurrences, in both jobs). This
  replaces Dependabot PRs #77 and #78. `actions/cache@v6` and
  `actions/upload-artifact@v7` untouched — out of scope.
- Existing shared concurrency group untouched — a new push still cancels
  the in-flight run for the same ref, for both jobs.

## Decisions
- `fast` filters on `github.event.action` rather than a separate `on:`
  block, because a workflow has one trigger set; per-job `if` is how two
  jobs can react differently to the same `pull_request` event.
- `fast` is unconditional (no label needed) by design — it is the free
  backstop; `build` keeps K21's label gate for the expensive browser/build
  half.

## Known issues
- Marking `fast` as a required check in branch protection is a founder
  step — not settable from this repo.

## Verification
`npx tsc --noEmit`, `npm run lint`, `npm test`, `npm run test:db`,
`npm run validate:content`, `npm run build` (with the two test env vars),
and `npx --yes js-yaml .github/workflows/ci.yml` all green — see the W1
dispatch report for exact command results.
