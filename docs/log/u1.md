# U1 — runtime flag store + `/admin/flags`

**Built**
- `lib/flags/keys.ts` — pure vocabulary: `FLAG_KEYS` (`ai_baby_paused` server-scope, `recomendados`
  client-scope), per-key scope/default/description, `mergeFlagRows`. Pinned by `lib/flags/keys.test.ts`.
- `lib/server/flags.ts` — `getFlag` / `getFlags` / `getClientFlags` behind a 60 s in-process cache,
  defaults with no `DATABASE_URL` and on any query error; `setFlag` writes the row and the audit row
  in one transaction.
- `appFlags` table (`drizzle/0015_dry_serpent_society.sql`), disposition `retained`, `flag_changed`
  audit action with meta `{ key, value }`.
- `GET /api/v1/flags` — no params (400, J3 pattern), client-scope keys only, `public, max-age=60`.
  Service worker: NetworkFirst with cached fallback. `useFlag(key)` returns the default until resolved
  and on any error.
- `/admin/flags` — one row per key (scope, description, state, who changed it last, toggle), nav link.

**Decisions**
- `setFlag` inserts the `adminAudit` row itself instead of calling `recordAudit`. `recordAudit` lives
  beside `requireAdmin` in `lib/server/admin.ts`, so importing it pulls next-auth into every flag
  reader — including the public route, whose parameter rejection has to be unit-testable
  (`api.test.ts`). The validation that matters, `parseAuditMeta`, is still shared, and
  `lib/flags/keys.test.ts` asserts no other file in `app`/`components`/`lib` names `appFlags`.
- Three pinned lists outside the Owns block had to grow, which is the mechanism they exist for:
  `ADMIN_ACTIONS` (`lib/admin/allowlist.test.ts`), the schema export (`lib/server/schema.test.ts`)
  and the retained-tables assertion (`lib/server/account.test.ts`, now `["adminAudit", "appFlags"]`).
- `updatedBy` is not a foreign key to `users`: A5's deletion must not be blocked by, or cascade into,
  the record of what was switched on. It resolves to nobody afterwards, like `adminAudit.actorUserId`.
- Every default is `false`, asserted. A store that cannot be read must fall back to the quieter app.
- Flags that gate money must be phrased as brakes (`*_paused`); a test fails any key ending `_enabled`.

**Known issues**
- The 60 s cache is per process. On a multi-process host a toggle is visible within a minute
  everywhere, not instantly — stated on screen and matched by the route's `max-age`.
- `/admin/flags` was not exercised signed-in: CI has no database and no OAuth. The e2e spec asserts
  the 404 for a non-admin; the toggle path is covered by unit tests over `setFlag` and the action.
- `recomendados` gates nothing yet — U3 mounts the rail, U11 links it.

**Verification** — `npx tsc --noEmit`, `npm run lint`, `npm test` (980), `npm run validate:content`,
`npm run build` with `DATABASE_URL` unset, `npx playwright test e2e/admin.spec.ts` (3 passed); against
the production build `GET /api/v1/flags` → `{"recomendados":false}`, `?x=1` → 400, `/admin/flags` → 404.
