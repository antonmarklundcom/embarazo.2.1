# R0-2 — /emergencia and /derechos missing from the service worker precache

Finding: `docs/log/r0.md` R0-2. README.md's "Qué funciona offline" section
(lines ~139-154) documents `/emergencia` (SOS numbers, alarm signs, saved
contacts) and `/derechos` as precached for offline use, but neither path was
in `app/sw.ts`'s explicit `pageRoutes` list — only `/`, `/guias`,
`/herramientas/comer`, `/preguntas`, `/herramientas/dental`, the 42
`/semana/[n]` routes, and the 8 guide slugs were. A phone that installs the
PWA and goes offline before ever opening `/emergencia` or `/derechos` got the
generic `/offline` fallback instead of the safety page — the worst possible
page to fail on.

## Fix

Added `"/emergencia"` and `"/derechos"` to `pageRoutes` in `app/sw.ts`,
alongside the existing entries, so they land in
`precacheEntries: [...(self.__SW_MANIFEST ?? []), ...pageRoutes]` the same
way `/herramientas/comer` and `/herramientas/dental` already do. No cache
names, route paths, or other entries changed.

## Why these two are safe to precache

Read `app/(app)/emergencia/page.tsx` and `app/(app)/derechos/page.tsx`. Both
are `"use client"` components with no server-only data fetch:

- `/emergencia` renders static copy (`lib/emergency.ts`) plus
  `useProfile()` and `useLiveQuery` reads against Dexie (`db().profile`,
  `db().clinical`) — same shape as `/` (already precached).
- `/derechos` renders a static catalog (`lib/derechos.ts`) plus
  `useProfile()`; the only input (work situation) is component state,
  never fetched.

Both are statically generated (confirmed in the build output below: `○
/derechos` and `○ /emergencia`, both prerendered), so they're eligible for
the same "list it explicitly" treatment the comment above `pageRoutes`
already describes for the week/guide routes.

## Verifying the built service worker

After `npm run build`, `public/sw.js` contains both new precache entries:
`grep -o '"/emergencia"\|"/derechos"' public/sw.js` prints both lines. The
build output also shows both routes prerendered as static (`○`), and the
existing `e2e/offline.spec.ts` (parameterized by URL, no hardcoded route
list) passed unchanged, confirming the precache/offline-fallback machinery
still works after the addition.

## Other README offline claims checked

The same "Qué funciona offline" section also lists the tools "Síntomas y
ánimo, Diario de fotos, Carné perinatal, Pataditas, Contracciones, Peso,
Checklist" as working offline, but attributes that specifically to their
data being local (IndexedDB) rather than to precaching — unlike the
`/emergencia` and `/derechos` bullets, it doesn't describe them as reachable
cold/offline on first install. Their routes
(`/herramientas/sintomas`, `/herramientas/diario` or `/fotos`,
`/herramientas/carne`, `/herramientas/pataditas`, `/herramientas/contracciones`,
`/herramientas/peso`, `/herramientas/checklist`) are indeed not in
`pageRoutes`. This reads as a different, weaker claim than the R0-2 finding
(local-data offline capability vs. cold-install precache), so they were left
out of this fix to stay within the R0-2 scope; flagged below for a
maintainer call on whether the README wording or the precache list should
change.
