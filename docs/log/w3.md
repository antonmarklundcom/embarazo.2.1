# W3 — photo alt text + measured hero contrast

**Built**
- Real alt text on the two user-photo `<img>` elements, from data the row already has:
  `app/(app)/herramientas/fotos/page.tsx`'s viewer now reads "Foto de tu panza, semana N,
  D de mes"; `app/(app)/herramientas/carne/page.tsx`'s viewer reads "Página N de tu carné
  perinatal, D de mes" (page number computed from the photo's position in the already-loaded
  list, since the viewer only had the single photo before). Both use the same
  `toLocaleDateString("es-PY", { day: "numeric", month: "long" })` pattern `sintomas`/`diario`
  already use for captions.
- `lib/hero/contrast.ts` (38 lines): `parseColor` (hex/rgb/rgba), `compositeOver` (alpha
  flattening), `relativeLuminance` and `contrastRatio`, pure WCAG 2.x. Unit-tested in
  `contrast.test.ts` against black/white (21:1) and #777/#fff (4.48:1), plus symmetry and
  `rgb()`-string parsing.
- `lib/hero/themes.test.ts` extended: for every theme, flattens the scrim's bottom-most stop
  over the background's bottom-most stop (the pixel under `WeekHeroImage`'s
  `inset-x-5 bottom-5` caption block), then flattens each `themeInk()` colour over that floor
  and asserts ≥4.5:1 for the eyebrow/soft (body) lines and ≥3:1 for the "Semana N" (large) line.

**Decisions**
- Read `themeInk()`'s actual returned colours rather than hardcoding an expected value, per the
  spec — this is the one place ink resolves to a concrete colour for the caption.
- Composited against each gradient's *last* stop (most favourable/most-opaque point on the
  scrim), not an earlier, less-opaque point the eyebrow line actually sits nearer to — the more
  conservative choice still fails, so a stricter measurement would only fail harder.
- Carne's viewer needed the photo's index to name the page; computed it in the page component
  from the already-loaded `photos` list (`findIndex` by id) and passed it down — no new field,
  no schema change.

**Known issues — flagged, not fixed**
- **5 of 6 themes measurably fail AA and are not touched, per the dispatch.** `halo`, `nanduti`,
  `estevia`, `alas` fail the body-text bar (eyebrow/soft ≈2.6–2.9:1 vs 4.5 required); `cielo`
  fails all three (eyebrow 2.21, soft 2.37, even the large "Semana N" line at 2.62 vs 3 required).
  Only `estrellas` passes (13.9/11.4/16.4). Root cause: the scrim's max opacity (0.38–0.42) is far
  too low against these pastel backgrounds' own lightness. `npm test` is red on these 5 assertions
  as a result — that is the measured truth this unit was asked to produce, not a mistake.
  Flagged to `docs/decisions-needed.md` for whoever may raise scrim opacity/ink in `themes.ts`.
