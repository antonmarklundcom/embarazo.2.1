# V1 — enforce the Content-Security-Policy

## Built
- `next.config.ts`: one enforced `Content-Security-Policy`. `Content-Security-Policy-Report-Only` deleted; the old `frame-ancestors 'none'` header merged into the policy rather than shipping a second CSP header beside it. Every other K14 header byte-identical.
- Sources added, each with the feature that needs it: `img-src https://*.googleusercontent.com https://*.fbcdn.net https://platform-lookaside.fbsbx.com` (provider avatars, `components/AccountCard.tsx`, rendered `unoptimized`); `img-src data:` (the base64 render from `/herramientas/bebe-ia`); `img-src blob:` (the K4 photo-diary preview); `connect-src <PHOTO_STORAGE_ENDPOINT origin>` (the presigned PUT/GET in `lib/photos/client.ts`, read at build time, absent when unconfigured); `frame-src https://www.youtube-nocookie.com` (the `/guias/videos` embeds); `worker-src 'self'` (the Serwist worker — `default-src` does not cover workers in every engine).
- Removed: the blanket `https:` from `img-src` and `connect-src`.
- `lib/zodJitless.ts` (new) + a side-effect import in the seven modules that build zod schemas: `config({ jitless: true })` in the browser.
- `lib/invariants/csp.test.ts` (new, 5 tests) — reads the config as text: no Report-Only, exactly one CSP header, `object-src`/`base-uri`/`frame-ancestors` intact, no wildcard host and no `unsafe-eval`/`data:` in `script-src`.
- `e2e/csp.spec.ts` (new, 9 tests) — a `securitypolicyviolation` listener installed before the first byte, over every sitemap URL (60), every tool page, `/offline`, `/cuenta`, `/ajustes`, `/familia`, `/admin`, then the service worker, onboarding, the share card, a `blob:` photo preview, a cross-origin presigned PUT, and the youtube-nocookie frame. Zero violations.
- `e2e/security-headers.spec.ts` — the Report-Only assertion replaced by two: the policy is enforced and single, and it names hosts rather than scheme wildcards.
- `.github/workflows/ci.yml` — one env var on the existing build step (see Decisions).

## Decisions
- **`script-src 'self' 'unsafe-inline'` kept**, as the queue decided. A nonce needs `middleware.ts`; the no-middleware invariant wins.
- **zod was calling `eval`.** Zod 4 feature-detects JIT with `try { Function("") }`. The throw is swallowed, so nothing broke — but it fired a violation and a console error on every page load, which is the noise that hides a real violation and would be the bulk of any future `report-uri` traffic. Fixed in the app (`jitless: true`), never in the policy. Browser-only: the server keeps the compiled path.
- **`PHOTO_STORAGE_ENDPOINT` added to CI's build env.** `headers()` is evaluated at **build** time and baked into `routes-manifest.json`, and a browser enforces CSP before Playwright's router sees a request — so `photo-backup.spec.ts`'s stubbed bucket was blocked, not routed. The endpoint only: no key, secret, region or bucket, so `isPhotoStorageConfigured()` stays false and the unconfigured half of that spec is unchanged. Same shape as the `NEXT_PUBLIC_SUPPORT_EMAIL` test value already on that step. Local gate runs need `PHOTO_STORAGE_ENDPOINT=https://bucket.example.test npm run build`.
- **Two files touched outside the Owns block**, both unowned by any other unit in this queue: `.github/workflows/ci.yml` (one env var; V3 and W1 edit other parts of it) and the seven zod modules plus the new `lib/zodJitless.ts`.
- **`form-action 'self'` kept.** Sign-in is a server action — a same-origin fetch — not a cross-origin form POST, so no provider origin is needed.
- **Side-effect imports carry the `.ts` extension** (`import "../zodJitless.ts"`), matching `lib/content/schemas.ts`: the `prebuild` script runs under `node --experimental-strip-types`, which will not resolve an extensionless specifier.

## Known issues
- `img-src` names Google's and Facebook's avatar CDNs by hostname. If a provider moves its CDN the avatar shows broken — the account card falls back to an initial only when `session.user.image` is absent, not when the image is blocked.
- `connect-src` carries no object-storage origin in a build where `PHOTO_STORAGE_ENDPOINT` is unset at **build** time. A deployment that sets it only at runtime would have photo backup blocked by its own policy.
- `'unsafe-inline'` in `script-src` remains the documented residual.
