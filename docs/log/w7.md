**Result: FAIL on all four URLs**, worse than W6's own baseline (where

| URL | Perf score | LCP | CLS | TBT | Budget met? |
|---|---|---|---|---|---|

| `/guias` | 72 | 3743 ms | 0 | 668 ms | No — score, LCP, TBT |

One anomaly worth recording rather than silently smoothing over: the first
of the three `/` runs failed outright with `EADDRINUSE :::3101` before the
script recovered and completed runs 2 and 3, so `/`'s median above is over
2 runs, not 3. `/semana/20`'s CLS (0.004995) matches W6's own reproducible
finding exactly, to the sixth decimal — good corroboration that the number
is real, not noise, and still under Lighthouse's 0.1 "good" threshold.

**Not treated as a new regression.** Per the dispatch's own note and
`docs/log/w6.md`, this is a documented pre-existing observation on a
contended dev machine, not something for this doc-only unit to chase. W6
already found `/` bimodal (~2000 ms quiet vs. ~4600–4800 ms contended); this
run's ~3900–3960 ms LCP sits inside that documented range, and all four
URLs failing at once (rather than just `/` and `/semana/20`'s CLS) is
consistent with heavier contention than W6 saw on its own runs, not with a
code change — nothing in this unit's diff touches app code, the home route,
or any of the four measured pages. Flagged for whoever picks up G3 to
re-measure on a quiet machine or in production.

## Deviations from the spec, and why

1. **The spec's own text says "Open the PR that turn."** The dispatch that
   started this session overrides that explicitly: "Do NOT push, open a PR,
   or merge... Commit your work locally on branch `unit/w7`." Followed the
   dispatch, not the older spec file — the dispatch is the more recent and
   more specific instruction, and the spec itself is silent on which wins
   when they conflict.
2. **Codex was not used anywhere in this unit**, per the dispatch's hard
   rule for this session; every gate, e2e run, and doc edit above was done
   directly.
3. **`docs/PLAN-2026-09-13-GO-LIVE.md`** is not in the spec's Owns block or
   read list, but the dispatch's "important context" section explicitly
   asked for it to be marked history in `docs/INDEX.md` alongside the 09-11
   queue, since it also fully merged. Only its `docs/INDEX.md` status line
   changed — its own body content was left untouched, same as every other
   file outside the Owns block.
4. **KNOWN-ISSUES.md's structure** (a new "From V1–V3, W6, R0" section
   rather than folding those items into U11's existing per-topic sections)
   was chosen so U11's original promotion pass and this one stay visibly
   separate — easier to audit which items each pass actually saw.
