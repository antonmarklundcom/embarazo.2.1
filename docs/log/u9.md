# U9 — AI-drafted answers inside the curated Q&A queue

## Built
- `lib/ai/draft.ts` (pure): kill switch (`AI_DRAFT_ENABLED` + `GEMINI_API_KEY`,
  same two-variable shape as `isAiBabyEnabled`), `aiDraftDailyCap`
  (fail-closed, default 20), the pinned system prompt (`buildDraftPrompt`: es-PY
  voseo, informational only, never diagnose or name a dose, always point alarm
  signs to control prenatal + `/emergencia`, ≤120 words, no markdown), and
  `sanitiseDraftText` (strips markdown, drops external links, keeps in-app
  routes).
- `lib/server/aiDraft.ts` (server-only): `generateDraft` — fail closed → check
  the daily cap (counted from `adminAudit` rows with action `draft_generated`)
  → write the audit row **before** calling the model → call it via an injected
  `DraftModel`, same shape as `ImageModel` in `lib/server/aiBaby.ts`. No
  `console.` in the module; the key is a header, never a query string.
  `draftAvailability` reports why the button should be hidden without
  generating anything.
- `app/admin/preguntas/actions.ts` (new): `suggestDraft` — authorise, validate,
  call `generateDraft`, return the draft or an error. Never publishes.
- `components/admin/AdminQuestionActions.tsx`: "Sugerir borrador" button
  (only rendered when `draftStatus` is passed in), fills the now-controlled
  answer textarea and shows "borrador generado por IA — revisá antes de
  publicar"; `draftStatus="capped"` shows the reason instead of a button;
  `draftStatus` left `undefined` renders nothing extra.
- `app/admin/preguntas/page.tsx`: computes `draftAvailability` once per page
  load (not per row — the cap is global) and only queries `adminAudit` when a
  database exists and the feature is configured.
- `lib/admin/audit.ts`: new action `draft_generated`, meta `{ questionId }`
  only, `.strict()`.
- `.env.example`: `AI_DRAFT_ENABLED`, `AI_DRAFT_DAILY_CAP`.

## Decisions
- The draft is generated from the question text posted back in the form
  (hidden field), not re-fetched from the database — avoids touching
  `lib/server/questions.ts` (not in this unit's Owns block) for a value the
  page already rendered to the admin.
- `drizzleDraftAuditStore.record` writes the `adminAudit` insert directly
  rather than calling `lib/server/admin.ts`'s `recordAudit`: that module sits
  next to `requireAdmin` and imports `./auth` (NextAuth's entrypoint), which
  is exactly why `setFlag` in `lib/server/flags.ts` does the same thing.
  Importing it would have made `lib/server/aiDraft.ts` (and its tests) drag in
  NextAuth. `parseAuditMeta` is still shared.
- `lib/admin/allowlist.test.ts`'s pinned `ADMIN_ACTIONS` list (not in this
  unit's Owns block) got one line for `draft_generated` — same append-only
  exception U1/U2 used for this exact list.

## Known issues
- No new Playwright coverage for "button absent when disabled": CI's existing
  `e2e/admin.spec.ts`/`e2e/preguntas.spec.ts` have no authenticated admin

  the Pausar button). Covered instead by `lib/server/aiDraft.test.ts`'s
  fail-closed and cap-logic unit tests against an in-memory store.
