# U3 — "Recomendados" rail (replaces E4)

**Built**
- `RecommendationSchema` in `lib/content/schemas.ts`: id/kind/title/body/ctaLabel, exactly one of
  `whatsappNumber`/`url`, optional `imageSrc`/`priceGs`, `stage` (0 = all, 1–3 = trimester), `priority`,
  `isSponsored` (default false).
- `lib/seed/recomendados.json` + `.ts`: 8 curated free resources, all verified in this session (web
  search, exact-URL match) — MSPBS portal, PAI vaccine schedule, IPS turnos, La Leche League Paraguay,
  Línea 155 salud mental, Registro Civil newborn registration, plus two entries that link **in-app** to
  `/derechos` (Ley 7383/2024, already computed there) and `/emergencia` (911/141/132, already tap-to-call
  there) rather than duplicating that content in JSON. No products — every entry is `kind: "recurso"`.
- `components/RecomendadoCard.tsx`, `components/RecomendadosRail.tsx` (self-gates on
  `useFlag("recomendados")`, mirrors `WeekArticleFeed`'s "render nothing" contract — **not mounted
  anywhere**, U11 does that) and `app/(app)/recomendados/page.tsx` (full list, same double gate).
- `app/api/v1/go/[id]/route.ts`: added `PUBLISHED_RECOMENDADOS` to the lookup; a recomendado without a
  `whatsappNumber` redirects to its `url` (resolved against the request origin, so an internal path like
  `/derechos` and an external `https://` URL both work).
- `app/admin/patrocinios/page.tsx`: recomendados resolve by id like placements/directory, kind
  "Recomendado".
- `scripts/validate-content.mts`: registered the new collection.
- `e2e/recomendados.spec.ts`: flag off → empty state, no `<article>`; flag on (mocked `/api/v1/flags`) →
  the stage-0 card renders and its CTA `href` is `/api/v1/go/rec-emergencia-numeros`.

**Decisions**
- `url` accepts an internal path (`/derechos`, `/emergencia`) as well as `https://` — added a schema
  refinement and a dedicated test rather than inventing a second field, because two of the six curated
  resources are things this app already explains in more depth than a JSON blurb could.
- Two files outside U3's Owns block needed a one-line, purely additive append to keep the build honest:
  `app/sw.ts` (precache `/recomendados`, same as the other static tool pages) and `app/sitemap.ts` (list
  it, same as `/directorio`) — both explicitly asked for by this unit's Build section. `lib/server/
  contentDebt.ts` needed a row too: its own test (`contentDebt.test.ts`) fails for any `lib/seed/*.json`
  with no row, the same pinned-list mechanism `ADMIN_ACTIONS` uses, and U3 is the unit adding the file.
- Direct `WebFetch` to verify each government URL was blocked by this session's egress proxy (only an
  allowlist of domains is reachable); verification instead relied on `WebSearch` returning the *exact*
  URL as a result (title and domain matching), which is what the CTA actually links to. Good enough to
  seed with confidence; not as strong as a live fetch, worth a human clicking each link once before launch.
- No `producto` entries: the founder has no real product yet (BUILD-PLAN E4), so seeding one would be
  exactly the "nothing real to show" failure this rail replaces.
- CTA always opens in a new tab (`target="_blank"`), even for the two internal-path entries — same
  pattern `ListingCard`'s "Cómo llegar" and `WhatsAppButton` already use. A tap on "Abrir modo emergencia"
  from the rail opens a second tab to the same PWA rather than navigating in place; acceptable, listed
  below as the one thing worth revisiting if it reads oddly on a real phone.

**Known issues**
- `RecomendadosRail` is unused until U11 mounts it on the home screen (by design — U3 must not touch
  `app/(app)/page.tsx`).
- The rail is not exercised in the e2e suite yet (nothing mounts it); only the `/recomendados` page is
  covered. U11 should add a rail-specific assertion once it is mounted.
- Two of eight resources' `whatsappNumber` fields were not usable — no WhatsApp/mobile number could be
  verified for La Leche League Paraguay (only landlines were found) — so every seeded entry uses `url`,
  not `whatsappNumber`; the `whatsappNumber` branch of the schema/card/route is exercised only by tests.
- Internal-path CTAs opening in a new tab (see Decisions) is a minor UX rough edge, not a correctness bug.
